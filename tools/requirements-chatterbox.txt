# Chatterbox TTS lives in its OWN virtualenv (tools/.venv-chatterbox),
# never the main environment tools/requirements.txt targets.
#
# Why: chatterbox-tts's dependency chain (a modern torch, unpinned
# transformers, tokenizers >=0.2x, diffusers, onnx, gradio, ...) directly
# conflicts with the pinned Kokoro/Whisper stack the rest of this repo's
# tools depend on (torch==2.14.0+cpu, transformers==5.12.1,
# numpy==1.26.4) -- installing chatterbox-tts into the shared/global
# Python silently downgrades those and breaks kokoro/whisper. Confirmed
# the hard way during the voice-audition session (2026-09-11): installing
# chatterbox-tts globally pulled torch 2.14.0+cpu -> 2.6.0, transformers
# 5.12.1 -> 5.2.0, numpy 1.26.4 -> 2.5.3, and broke `import kokoro`.
#
# Setup (one-time):
#   cd tools
#   python -m venv .venv-chatterbox
#   .venv-chatterbox\Scripts\python.exe -m pip install --upgrade pip
#   .venv-chatterbox\Scripts\python.exe -m pip install -r requirements-chatterbox.txt
#
# capy_tts.py invokes tools/capy/_chatterbox_worker.py as a SUBPROCESS
# using .venv-chatterbox's python -- never imported in-process -- exactly
# like tools/transcribe.py already shells out to a separate `whisper`
# CLI process rather than importing it in-process (same reasoning:
# process isolation from the caller's own dependency stack).

chatterbox-tts>=0.1.7

# chatterbox-tts's own dependency `resemble-perth` (the audio
# watermarker) imports `pkg_resources` at import time, which setuptools
# >=81 removed. Without this pin, ChatterboxTTS.from_pretrained() raises
# `TypeError: 'NoneType' object is not callable` when it tries to
# construct PerthImplicitWatermarker (perth.PerthImplicitWatermarker
# silently becomes None on the failed import instead of raising).
setuptools<81
