# Chart style guide

This is the house style for the hand-rolled SVG/HTML chart primitives under
`src/components/charts/` and their call sites (channel growth, the premium
comparison chart, the eternal-increase timeline). It draws on Ryan Burge's
(Graphs About Religion, @ryanburge) ggplot2 conventions — direct labeling,
minimal gridlines, highlight-vs-gray, a fixed caption grammar — translated
onto this site's own tokens and fonts rather than copied wholesale. Read
[BRANDING_AND_DESIGN.md](../BRANDING_AND_DESIGN.md) first; this file is the
detail behind its five-line "Charts" section.

**Scope.** This guide covers the in-app SVG/HTML chart primitives only —
`palette.ts`, `scales.ts`, `hover.ts`, `chart-tooltip.tsx`,
`direct-labels.tsx` — used by hand-built pages that need their own
interactive chart. **Every graphic on a dataset's `/data-explorer/<slug>/graphics`
page is a downloadable PNG, generated by a Python script, not an in-app
component.** That pipeline (`scripts/state-of-theology-graphics/STYLE.md`,
`scripts/pew-rls/STYLE.md`, `scripts/ryan-burge/STYLE.md`,
`scripts/social-graphics/STATISTICS_STYLE_GUIDE.md`, and the shared
`scripts/chart_style.py` helpers) is a separate design system — white
canvas, Roboto Slab, its own hardcoded palette — because these images have
to stand alone once downloaded and shared off-site. The two systems share
reasoning (accurate, spin-free titles, every number traceable to a source,
nothing hand-typed, direct labels over legends, highlight-vs-gray, decline
is always the site's oxblood token) but not tokens or components. Don't
import one pipeline's colors into the other's charts.

**History.** This kit used to include a higher-level layer —
`ChartFrame`/`ChartCaption`, `StackedBars`, `DotPlot`, `WaveLineChart`,
`FacetGrid`/`MiniBars` — purpose-built for a `/graphics` page "Interactive"
section that ran an in-app chart alongside a same-titled downloadable PNG.
That twin pattern was retired 2026-08-26: every dataset's `/graphics` page
now shows the PNG only, so those five components (and the
`src/components/charts/figures/` registry that wired them into datasets)
were deleted rather than left unused. If a future page genuinely needs an
in-app 100%-stacked bar, dot plot, or wave-line chart again, rebuild from
this guide's anatomy/axis/label/color rules below and the deleted
components' git history (`46f0965`, the commit that first added them) —
don't resurrect the twin pattern that motivated removing them.

## Axes and gridlines

- **No axis titles, ever.** A title and subtitle should carry that meaning
  instead of `x`/`y` labels nobody reads.
- **Delete the value axis entirely** once every mark carries its own printed
  label — the axis becomes redundant and just adds ink.
- **One axis of gridlines, not two.** Major lines solid `var(--border)` 1px;
  minor lines the same, dashed `4 2`. No tick marks on the rule itself.
- **Explicit category ticks** on a wave/wave-year axis — the real survey
  years, not interpolated date ticks.
- Percent values are formatted `42%`, not `42.0%`, unless the spread in the
  data genuinely needs the extra digit (`fmtPctLabel` in `scales.ts` takes a
  `decimals` override for that case).

## Direct labels over legends

- **Every mark prints its own value where practical.** Suppress a label
  once it can't fit — a number that can't fit reads worse than no number.
- **Label the line, not the legend.** A line chart's series are named at
  their last point (`EndOfLineLabel` in `direct-labels.tsx`), not in a
  legend box competing for the reader's attention.
- When a legend is genuinely unavoidable, put it below the chart, no title,
  in the same order the data reads.

## Color assignment

- **`SERIES_PAINT`** (`palette.ts`) is the canonical order for a chart with
  no natural focal series: `--accent`, `--honey`, `--oxblood`, `--foreground`
  — the same four ink families the rest of the site already uses, so a
  chart never introduces a color the reader hasn't learned elsewhere.
- **Hard cap: 4 distinct chart colors** (`MAX_SERIES`). This is why the
  premium comparison chart caps channel selection at four.
- **Highlight-vs-gray.** When one series is the point of the chart (LDS
  against several other groups), draw the focal series in a house color and
  every other series in `CONTEXT_GRAY` (`var(--muted)`) at reduced opacity,
  labeled at the line's end. Grayed context series **do not count against
  the 4-color cap** — that's how a chart legitimately carries seven lines
  and still reads cleanly.
- **Decline is always `var(--oxblood)`.** Growth/positive change is always
  `var(--accent)`. Don't reassign these on a chart-by-chart basis.
- Every mark gets a **1px `var(--border)` stroke** — the thin-outline tic
  that makes flat fills read as discrete marks rather than a smear of
  color.
- Dots use the "shape-21" treatment: series-color fill, `var(--foreground)`
  outline at 1.5px, knocked out from whatever's beneath with a
  `var(--surface)` circle first — the same `ring-[color:var(--surface)]`
  knockout rule `BRANDING_AND_DESIGN.md` already documents for badges.

## Uncertainty and reference lines

Any dashed reference line (a sample average, a "no change" zero line, a
comparison group's value) must carry a short text label — never a bare line
the reader has to guess the meaning of.

## Dark mode, accessibility, and hover

- **All paint is a literal `var(...)` string** — `palette.ts`'s maps, never
  a computed class name or a raw hex. Tailwind v4 can't see a constructed
  class, and SVG paint attributes take a CSS variable directly, so this is
  free dark-mode support with zero `dark:` variants anywhere in a chart.
- **All chart text is an HTML overlay, percent-positioned over the SVG —
  never SVG `<text>`.** Every chart here sets
  `preserveAspectRatio="none"` on its `<svg>` so the plot fills its box
  exactly; that same setting stretches SVG text unevenly. An HTML overlay
  also inherits the site's fonts and theme automatically.
- Root SVG carries `role="img"` and an `aria-label` built from the data
  itself.
- Numbers are always `tabular-nums`.
- Hover is a bonus, not the only way to read a chart — every value that
  matters is already printed as a direct label. `hover.ts`'s
  `nearestByX`/`nearestDot` generalize the pointer-hit-testing logic; don't
  reimplement per-dot hit circles (see `nearestDot`'s comment for why).
- **Empty state**: a dashed-border card with a muted one-line explanation —
  the existing pattern in `growth-chart.tsx` and `comparison-chart.tsx`.
- Charts add no animation; if one ever does, gate it on
  `prefers-reduced-motion` per `BRANDING_AND_DESIGN.md`'s Motion section.

## Axis-domain honesty

Carried forward from `graph-shared.ts`'s original comments, now policy for
every chart, not just the timeline:

- **Pin a time axis to the whole relevant span, not just the plotted data**,
  when an absence is itself informative — a question last raised a decade
  ago should show a decade of empty space, not silently rescale until its
  last point sits at the (falsely current-looking) right edge.
- **Report the true first/last data point in captions even when the axis
  is padded** to round numbers for layout — the axis bounds and the caption
  bounds are allowed to differ, but the caption must never overstate them.
- **Redundant encoding for color-blind readers**: where position and color
  both carry the same information (a lane plus a color, a sort order plus a
  highlight), keep both — don't drop the redundant channel to save a pixel.
- **Nearest-wins pointer hit-testing with a give-up radius**, not a hit
  circle per mark — dense axes overlap per-mark targets and the last-painted
  one silently wins; a single generous hit-test layer keeps every mark
  reachable at any chart width.

## Data-explorer graphics: PNG only, nothing hand-typed

Every graphic on a dataset's `/data-explorer/<slug>/graphics` page —
without exception, no in-app "Interactive" companion — is:

1. A Python script (`scripts/<dataset>/*.py`) that computes real numbers
   from the source microdata into a committed JSON file. No chart anywhere
   in this pipeline has a hand-typed number.
2. A second Python script (`scripts/<dataset>/render_*.py`, matplotlib +
   the house PNG fonts/canvas — see each folder's own `STYLE.md`) that
   renders that JSON to a 1080×1350 PNG under `public/data-explorer/<slug>/`.
3. A `Graphic` entry in `src/lib/data-explorer.ts`, built from the same
   JSON the render script reads, so the image and its alt text can never
   drift apart.

When adding a new data-explorer graphic: write the compute script, write
the render script (copy an existing one in the same dataset's `scripts/`
folder as a starting point rather than inventing new canvas/font
boilerplate — every new render script should import
`scripts/chart_style.py` for its caption placement and font-size floors
rather than hand-rolling either), regenerate the PNG, then add the
`Graphic`-building function to `data-explorer.ts` and wire it into that
dataset's `graphics: [...]` array. See `scripts/pew-rls/STYLE.md` for the
palette/layout rules the Pew RLS charts follow, that folder's
`render_switching_generalized_chart.py` and `render_birth_decade_chart.py`
for two different chart shapes (100%-stacked bar, ordinal-ramp
100%-stacked bar), and
`scripts/ryan-burge/STYLE.md` for the pipeline's one heatmap/matrix shape
(tri-color diverging gradient). Before calling a render done, read
`scripts/state-of-theology-graphics/STYLE.md`'s "Always check for overlap
and spillover" section — open the actual PNG and check for it, every time
a layout changes, not just the first render.

## Study graphics: the same pipeline, keyed by study slug

Per-study graphics on `/studies/<slug>` (and their
`/studies/<slug>/graphics[/<graphicId>]` routes) are the same PNG pipeline
pointed at the research library instead of a dataset: every number lives
once in `docs/study-data/<study-slug>/data.json` (transcribed from the
publication, with a `sources` array citing the exact table/page — the
practical equivalent of "nothing hand-typed" when microdata isn't
available), rendered by `scripts/study-graphics/<study-slug>/render_*.py`
into `public/study-graphics/<study-slug>/`, and registered in
`src/lib/study-graphics.ts` (which imports the same JSON for alt text).
See `scripts/study-graphics/STYLE.md` for the folder contract, the
current-vs-former group-color convention, and the `dataExplorerSlug`
cross-link rule for studies whose data an existing dataset already
charts.
